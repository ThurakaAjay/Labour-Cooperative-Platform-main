# 🚀 WorkHive Production Deployment Guide & Checklist

This guide walks you through deploying **WorkHive** to production.

---

## 📋 Pre-Deployment Checklist

- [ ] **Push Local Code to GitHub**:
  Your local repository has 6 commits ahead of GitHub. Run:
  ```bash
  git push origin main
  ```
- [ ] **MongoDB Atlas Database**:
  Ensure your MongoDB Atlas cluster has network access enabled (`0.0.0.0/0` or cloud provider IP whitelist) and you have the connection URI ready.
- [ ] **Cloudinary Account**:
  Ensure you have your Cloud Name, API Key, and API Secret from [cloudinary.com](https://cloudinary.com).

---

## 🌟 Option 1: Render (Recommended — Easiest & Free)

Render allows you to host the unified full-stack application (both API and React Frontend) under a single service with zero CORS issues.

### Step 1: Connect Repository to Render
1. Go to [dashboard.render.com](https://dashboard.render.com/) and log in.
2. Click **New +** → **Blueprint**.
3. Select your repository: `Labour-Cooperative-Platform` (or `WorkHive`).
4. Render will detect `render.yaml` automatically.

### Step 2: Configure Environment Variables
Render will prompt you to provide the required environment variables:
| Variable Name | Recommended Value / Source |
|---|---|
| `NODE_ENV` | `production` |
| `MONGODB_URI` | Your MongoDB Atlas connection URI string |
| `JWT_SECRET` | Auto-generated by Render (or any 32+ character random string) |
| `ADMIN_EMAIL` | Your administrator email (e.g., `admin@yourdomain.com`) |
| `ADMIN_PASSWORD` | Strong password for the admin account |
| `CLOUDINARY_CLOUD_NAME` | Your Cloudinary Cloud Name |
| `CLOUDINARY_API_KEY` | Your Cloudinary API Key |
| `CLOUDINARY_API_SECRET` | Your Cloudinary API Secret |
| `CORS_ORIGIN` | Leave blank (auto-permitted) or your custom domain |

### Step 3: Deploy
1. Click **Apply**.
2. Render will run `npm run build` (builds both server deps and Vite client bundle).
3. Render starts the application with `npm start`.
4. Your application will be live at `https://<your-app-name>.onrender.com`!

## ⚡ Option 2: Decoupled Deployment (Vercel Frontend + Render Backend)

If you prefer global edge CDN performance for your React frontend:

### Part A: Deploy Backend to Render
1. In Render, click **New +** → **Web Service**.
2. Connect your repository.
3. Configure settings:
   - **Root Directory**: `server`
   - **Build Command**: `npm install`
   - **Start Command**: `node server.js`
4. In **Environment Variables**, add:
   - `NODE_ENV=production`
   - `PORT=5000`
   - `MONGODB_URI=<your-atlas-uri>`
   - `JWT_SECRET=<strong-random-key>`
   - `ADMIN_EMAIL=<admin-email>`
   - `ADMIN_PASSWORD=<admin-password>`
   - `CLOUDINARY_CLOUD_NAME=<cloud-name>`
   - `CLOUDINARY_API_KEY=<api-key>`
   - `CLOUDINARY_API_SECRET=<api-secret>`
   - `CORS_ORIGIN=https://<your-vercel-domain>.vercel.app`
5. Note down your backend URL (e.g. `https://workhive-api.onrender.com`).

### Part B: Deploy Frontend to Vercel
1. Go to [vercel.com](https://vercel.com/) and click **Add New...** → **Project**.
2. Import the `Labour-Cooperative-Platform` repository.
3. Configure project settings:
   - **Root Directory**: `client` (click Edit and select `client`)
   - **Framework Preset**: `Vite`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. Under **Environment Variables**, add:
   - `VITE_API_URL=https://<your-render-backend-url>/api`
5. Click **Deploy**.
6. The included `client/vercel.json` ensures that deep routing (e.g. `/worker`, `/admin`, `/customer`) works cleanly without 404s.

## 🐳 Option 3: Docker / Docker Compose / Self-Hosted VPS

If deploying to your own Linux server (Ubuntu/Debian) or cloud VM:

### Using Docker Compose
1. Clone the repository on your server:
   ```bash
   git clone git@github.com:Swarajbabu/Labour-Cooperative-Platform.git
   cd Labour-Cooperative-Platform
   ```
2. Copy `.env.production.example` and fill in secrets:
   ```bash
   cp .env.production.example .env
   ```
3. Start the stack with MongoDB:
   ```bash
   docker compose up -d --build
   ```
4. Access the application on `http://<server-ip>:5000`.

## 🔍 Post-Deployment Verification

Once deployed, perform these verification checks:

1. **System Health Probe**:
   Visit `https://<your-domain>/api/health`. You should see:
   ```json
   {
     "status": "ok",
     "service": "WorkHive Enterprise API Server",
     "database": {
       "engine": "MongoDB",
       "status": "connected",
       "connected": true
     }
   }
   ```

2. **Frontend UI Check**:
   Visit `https://<your-domain>/`. The WorkHive landing page should load with trade categories and icons.

3. **Admin Login**:
   Navigate to `https://<your-domain>/login?role=admin`.
   Log in with the `ADMIN_EMAIL` and `ADMIN_PASSWORD` you configured.
   You should successfully access the Cooperative Officer Administrative Dashboard.

4. **Customer & Worker Registration**:
   Test registering a new customer or worker account to verify that JWT issuance and database persistence operate correctly.
