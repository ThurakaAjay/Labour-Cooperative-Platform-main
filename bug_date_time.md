## Proactive Improvements (beyond the original checklist)

1. **Arrival-PIN leak to the worker's own client** — found while wiring PIN verification: the worker's app was shown the exact PIN it was supposed to be independently told by the customer, making the "security" check theatre. Added server-side redaction (`redactPinForRole`) across every booking response path a worker can reach.
2. **`multer` pinned to the actively-maintained 2.x line** instead of the 1.x line originally drafted, since 1.x carries several disclosed vulnerabilities.
3. **CSP hardening for new external calls**: extended `helmet`'s Content-Security-Policy to explicitly allow only `checkout.razorpay.com` (script/frame), `api.razorpay.com` (connect/frame), `res.cloudinary.com` (img), and the OpenStreetMap tile subdomains (img) — every other third-party origin remains blocked by default.
4. **Razorpay webhook raw-body capture**: added `verify` capture on the global JSON body parser so the webhook route can validate Razorpay's HMAC signature against the exact bytes Razorpay signed, rather than a re-serialized (and potentially mismatched) JSON object.
5. **Payment idempotency**: both the client-verify path and the server webhook path settle a payment through the same `_settlePayment` routine, guarded by a `status: { $ne: 'paid' }` conditional update — a booking can't be double-credited if both paths fire for the same payment.
6. **`WorkerDashboard.jsx` unused destructured `customerRating`** field (always `undefined`, silently rendered nothing) removed.
7. **Existing, unrelated moderate vulnerabilities** flagged but intentionally **not** force-upgraded (would require breaking major-version bumps out of this task's scope):
   - Server: `express`/`body-parser` → transitively vulnerable `qs` (no non-breaking fix available yet).
   - Client: `vite` (dev-server-only esbuild advisory) and `react-router-dom` (open-redirect advisory) — both only resolvable via a major-version upgrade (Vite 8 / React Router 7).
8. **An external commit (`d891510`) landed on this repo mid-audit**, under the project owner's own git identity, while this session was still reading pre-audit file state. All fixes above were built and verified against the post-commit code, not the earlier snapshot.
